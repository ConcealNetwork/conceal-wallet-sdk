Authenticated wallet envelope v3 (Argon2id)

Change: authenticated-wallet-envelope-v3 · SDK: bump to 0.3.0

In plain language

Wallet JSON backups and in-app stored wallets will be encrypted with Argon2id (memory-hard password hashing) plus the same secretbox cipher as today. Older Conceal files still open. Every new save or download is Envelope 3. Apps on SDK 0.2.x cannot open those new files — next-wallet and Get NowHere must bump together after this release.

Downloads create a new file. The user’s original imported JSON is never deleted or overwritten by export. Device storage upgrades 1/2 → 3 only after a verified decrypt of the new blob.

Envelope versions

  • 1 — legacy inline (only keys encrypted)
  • 2 — legacy whole-blob pad/clamp password
  • 3 — Argon2id + authenticated KDF metadata (only format we write)

Inner wallet JSON is still called RawWalletV1 — that is not the envelope version.

Flow

import / storage JSON
        │
        ▼
parseEncryptedWalletJson  (reject if > 32 MiB text)
        │
        ▼
openEncryptedWallet
  envelope===3? → Argon2id path only
  else data[]?  → legacy env 2
  else encKeys? → legacy env 1
  else → null
        │
        ▼
OpenedWallet { raw, keys, envelope }
        │
        ├─ env 1|2 + storage open → migrateToEnvelope3 → verify → setItem(v3)
        └─ env 3 → return (no rewrite on open)

What operators should check after implement

  • Legacy fixtures still unlock
  • New saves show "envelope": 3 and Argon2id kdf
  • Wrong password / tampered params → null
  • Storage migrate only when round-trip verify succeeds
  • npm run types && npm run lint && npm test green
